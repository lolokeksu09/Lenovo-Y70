# Lenovo Y70 — v3.1 safety audit

## Scope

Android package: `com.moto.resolutionmaster`. Built from the pinned public upstream `f1rzen-n/LenovoMotorolovichY70@10ffc78b9c97326467dc457513d6182581416991` plus the versioned `overrides/` tree.

### Commands and permissions
- `ShellHelper.CommandResult` records a shell exit code and diagnostic output for critical operations. A zero exit code **does not** prove a device setting took effect; callers must re-read state.
- `WRITE_SECURE_SETTINGS` is verified by checking the Android permission after the grant request.
- Existing legacy commands outside the migrated paths still need individual readback audits.

### Debloater
- Package disable/enable validates the actual `PackageManager` state after each operation, rather than trusting the exit code or SharedPreferences.
- A durable journal records packages that were enabled just before this app attempted to disable them. It is saved before issuing the command, to support recovery after process death.
- Preset switching and bulk rollback re-enable **only packages recorded by v3.1**; manually disabled packages and older changes are not silently overwritten.
- Essential system packages and the current default launcher are protected; protected Motorola packages are refused instead of being falsely shown as AppOps-frozen.
- Failed or incomplete operations are reported as partial results.

**Migration limitation:** earlier v2.x/v3.0 debloat changes have no reliable per-package journal; v3.1 cannot safely infer ownership. Do not use a blanket system reset as a substitute.

### NFC
- Before apply/rollback, inspect available current routing; unsupported or unreadable controllers cause a safe refusal.
- After a successful helper response, re-read routing; only the confirmed target state is reported as successful.
- Do not automatically retry with force operations or remove other Magisk modules. Explicitly exported rollback ZIP affects only this app's own NFC module.
- DH routing status does **not** prove payment compatibility. Payments require testing on the actual device and terminal.

### Checks and delivery
- `python tests/check_static.py` and `python tests/check_v31.py` check explicit source invariants.
- GitHub Actions compiles, D8-dexes, signs a **debug** APK and verifies its ZIP structure.
- Actual NFC control, hardware DC Dimming, system refresh modes, Debloater restore and device-specific PMIC functions remain **NOT VERIFIED on the phone**.
- CI debug signature can differ from an installed APK. Back up data before uninstalling anything.
