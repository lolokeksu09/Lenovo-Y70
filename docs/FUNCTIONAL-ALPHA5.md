# Functional alpha.5
Scope: expand behavior rather than reshuffle modules. Auto foreground cleanup is off by default, uses SOFT/native only, requires consecutive valid samples and retains policy guard. Interval is monotonic within the ViewModel lifetime; process restart resets it. WorkManager alerts are opt-in, use one periodic job (15 min minimum, no exact timing), check settings again before delivery, and never invoke cleanup. Widget uses Android MemoryInfo, refresh action and scheduled update; tile uses Android 14+ PendingIntent API, shows available memory on panel entry and launches the app. Neither launches pressure from a background component. Journal distinguishes triggers and summarizes measured results.
Existing preference keys and legacy history retained. Native limits unchanged. Fully user-defined allocation sizes beyond preset safety caps, true automatic background cleanup, screen-off triggers, per-process PSS rankings and device tests are not included. Before release: check consent/denial, worker cancellation/reboot/Doze, widget refresh on launcher, tile on API 26/34+, foreground loss, threshold crossing, interval, pressure guard, journal update.

Added structured Shizuku memory report: per PID PSS/RSS/Swap PSS, unknown values remain unknown; legacy fallback for PSS, raw output retained. Bounded subprocess with hard timeout and truncation warning. Diagnostics can include other Android profiles; no cross-profile command expansion. Target process measurements are unverified on device.

Manual native limits are persistent, support a smaller cap and hold (including no hold), and are enforced in the domain controller. No increases beyond the selected preset or global Rust cap. Automatic runs use unchanged SOFT defaults. Diagnostic requests are single-flight until the current Binder read returns; dismissing hides stale output, not falsely cancelling an in-flight shell command.
