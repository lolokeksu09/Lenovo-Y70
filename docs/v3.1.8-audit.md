# LenovoMotorolovichY70 v3.1.8 — audit

Date: 2026-11-19. Scope: GitHub source code and GitHub Actions APK build; not a physical Lenovo Y70 device test.

## Verified by source inspection

| Finding | Evidence / consequence | v3.1.8 action |
| --- | --- | --- |
| Experimental automatic enable used Accessibility | The feature needed a separately enabled AccessibilityService, observed `com.android.settings` windows and clicked UI buttons. No confirmed successful run on this Lenovo firmware. Broad permission for an unverified convenience feature. | Remove service class, helper, manifest registration, XML, consent/onboarding UI and CI tests entirely. |
| Manual recovery already exists | `openPackageDetailsForRestore` opens `Settings.ACTION_APPLICATION_DETAILS_SETTINGS`; `verifyReturnedSettingsPackage` re-reads state. User earlier confirmed two packages changed from `enabled=2` to `0` through Android Settings. | Keep and retest manual guided recovery without Accessibility. |
| Shizuku shell limited by Android | `enabled=2` returned `SecurityException: Shell cannot change component state`; using Shizuku is not equivalent to system privileges. | Keep `RestoreRoute`: `enabled=3` eligible for `pm enable`; `enabled=2/4` use manual Settings page. |
| Nonfunctional 'Freeze (AppOps)' UI | `PackageHelper.disablePackage` explicitly refuses protected packages, yet AppListAdapter/preset still offered 'Заморозить' and claimed 'Заморожено (AppOps)'. | Show true status and nonclickable 'Защищено системой'; do not claim AppOps was changed. |
| Preset status conflated absent and unknown with disabled | `disabledCount++` ran on `!enabled`, and `isPackageEnabled` collapsed null and false. | Count only installed packages with verified `Boolean.FALSE`; show 'Состояние неизвестно' separately and disable the unsafe action. |
| Recent Disabled-filter race | Adapter previously began with filter 0 when the user selected Disabled before initial scan; user confirmed v3.1.7 fixed it. | Preserve `DebloatFilterSelection` and run existing regression tests. |

## Unresolved / not validated on real hardware

- Manual preset buttons still issue potentially slow system calls from the UI thread. Refactor to background execution in a separate, focused change; do not pretend this release fixes UI stalls there.
- Confirmation of hardware NFC routing, OLED/DC dimming, bypass charging and refresh-mode writes requires device-level observation. Some hardware functionality remains deliberately disabled when unavailable.
- The application cannot silently restore manufacturer-disabled `enabled=2` packages using shell UID 2000; opening Android Settings retains explicit user control.
- GitHub Actions debug-signed APK can be incompatible with a previously installed differently signed APK. Back up app data before uninstalling.

- Behavioral JVM regressions: existing package-state, disabled-filter, bulk-enable, recovery routing and async-filter selection suites.
- Android CI: Java compile, D8, debug signature and zipped APK structure.

All removals affect the current tracked tree. Old commit history is not rewritten.
