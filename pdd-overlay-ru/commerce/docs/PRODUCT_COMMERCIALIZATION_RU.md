# PDD Overlay RU — подготовка к коммерческому выпуску

**Исходная версия Android:** v0.1.8, `app.pinduoduo.overlayru`. Дата анализа: 2026-11-14.

## Решение

Сначала выпустить отдельный сервер лицензий и провести закрытый пилот, затем интегрировать клиентскую проверку с подписанными офлайн-разрешениями. Не выпускать платную сборку на неподтверждённо стабильном оверлее.

### Почему не просто проверка ключа в APK

Клиентский код можно патчить, захардкоженный ключ и списки действующих серийников извлекаются. Серверная выдача RS256-токена с ограниченным сроком, хранение хеша активационного ключа и проверка с публичным ключом в APK сложнее для массового обхода. **Это не абсолютная DRM-защита.**

## Модель продукта

- Бесплатная версия остаётся функциональной: уже существовавший в v0.1.8 китайский и английский перевод не отключается автоматически у тестовых пользователей.
- PRO вводится после появления реальной дополнительной ценности: расширенные правила размещения, собственный словарь, запоминание коррекций, OCR после технического и правового анализа. **Не продавать ещё не реализованный OCR как текущую функцию.**
- Для пилота — ключи на 30 или 365 дней, ручная выдача после подтверждённой оплаты. Автопродление — после появления надёжных платежей и поддержки отмены/возвратов.
- Предварительный ценовой эксперимент: 199 ₽/30 дней, 990 ₽/365 дней. Это гипотезы для измерения спроса, не доказанные рыночные цены.
- Ключ на 1 установку, перенос по запросу в поддержку. Не привязываться к IMEI, SIM, hardware serial или SSAID; минимизировать персональные данные.

## Приоритеты запуска

### P0 — товарное качество

1. Проверить overlay на устройстве: смена окон, быстрый скролл, WebView, поворот, плавающая кнопка, отсутствие перекрытия оплаты.
2. Перевод не должен маскировать стоимость, валюту, количество, адреса, важные предупреждения и кнопки подтверждения транзакции.
3. Базовая навигация без зависаний, обнаружение наличия моделей офлайн, загрузка через мобильную сеть и информативные ошибки VPN.
4. Настоящий onboarding: согласие на Accessibility отдельно от включения службы; раскрытие назначения и объёма доступа, без манипуляций.
5. Анонимная техническая диагностика только по добровольному согласию, без содержимого экрана.

### P1 — лицензии

1. Сервер выдачи/продления/отзыва лицензий, отсутствие секретов в APK (реализован прототип в `license-server`).
2. Проверка RS256 и контракта claims на Android; экран статуса: Free / PRO / до какого числа / ошибка связи / активировать ключ.
3. Ограниченный офлайн-период, честное поведение при истечении срока, без бесконечных повторов или блокировки интерфейса.
4. Настоящий механизм управления активациями и восстановления после смены телефона.
5. Интеграционные тесты: действительный ключ, повторная активация, истёкший ключ, отзыв, смена устройства, сломанные часы, нет интернета.

### P2 — продажи

1. Выбрать канал: RuStore Pay SDK для RuStore либо подтверждённый платёжный провайдер для APK вне магазинов. Не смешивать разные правила оплаты.
2. Платёжные вебхуки с криптографической проверкой, идемпотентностью и защитой от повторного исполнения.
3. Публичные условия подписки, отмены и возвратов, поддержка, чек/налоговый режим с учётом юрисдикции.
4. Безопасное хранение данных и резервные копии, измерение отказов лицензирования без собирания текста переводов.
5. Распространение подписанного APK через устойчивый HTTPS-хостинг/релизные assets, а не через ссылки, которые у пользователя дают `Library file not found`.

## Правовые и платформенные ограничения

- **Google Play / Россия:** встроенные платежи Google Play для пользователей из России приостановлены; для разработчиков с российскими банковскими счетами действует отдельная приостановка выплат. Решение о распространении не должно исходить из того, что Google Play Billing доступен.
- **RuStore:** требуется декларировать платёжные решения, права на бренд и материалы; для потенциально чувствительного Accessibility-разрешения необходимо обосновать его использование. В 2026 используется Pay SDK вместо снятого с поддержки BillingClient SDK.
- **Google Play Accessibility:** для переводчика, не позиционируемого как инструмент помощи людям с инвалидностью, нужны отдельное информирование внутри приложения и явное согласие; не ставить `isAccessibilityTool=true` без оснований.
- **ML Kit:** SDK бесплатен, но on-device Translation API имеет отдельные требования к атрибуции Google и обработке метрик SDK. Переводимый текст обрабатывается на телефоне; ML Kit может получать технические метрики и обновления моделей. Текущее описание «никогда ничего не передаёт Google» было бы неточным.
- **Чужой бренд:** пока не доказано разрешение правообладателя, не представлять приложение официальным клиентом Pinduoduo и не использовать чужие логотипы как свой. Выбрать самостоятельный бренд перед коммерческой публикацией, согласовать изменение applicationId (при смене packageId старые APK не обновятся поверх новой версии автоматически).

## Границы выполненной работы

Реализован **отдельный прототип сервера лицензий**, не интегрированный в Android. Это не запущенная подписка и не опубликованный продакшен API. Ключи и деньги реальных клиентов не выдавались и не принимались. Сохранены файлы и поведение существующего v0.1.8 APK.
