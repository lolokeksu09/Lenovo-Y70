# PDD Overlay RU v0.2.0-beta.5 — OCR file opening and screen redesign

## Fixed
- Replaced a fragile two-pass `BitmapFactory.decodeStream` image loader. On Android 9+ first use the system's URI-aware `ImageDecoder`, supporting common gallery and content-provider formats (including device-supported HEIC/WebP). For providers/codecs where that fails, use a bounded **single-read** `BitmapFactory.decodeByteArray` fallback.
- Added source-size validation and decoded-size downsampling. Files above 24 MiB or invalid/huge bitmaps fail safely, with specific guidance instead of the incorrect generic "choose JPG or PNG" message.
- Keep an independent small image preview while ML Kit processes the full bitmap, so recycling the source bitmap cannot blank the UI.
- OCR translation now processes a few lines at a time instead of submitting up to 60 to the shared request queue concurrently. Stale selections and timed-out requests cannot overwrite newer results.

## UI and layout
- Explicit near-black AMOLED background (the old theme-only setup left the Activity window's charcoal background visible).
- Smaller consistent primary action, actual image preview and a compact model-settings row.
- Clear empty, busy, image-unavailable, no-text and successful-results states, with text explaining how to recover.
- Results displayed in one scrollable, separated list with original and translated lines, a line count and a copy button.
- Appropriate 48 dp touch targets, compact typography, accessible announcement of progress changes and maximum 580 dp content width.

## Compatibility, privacy and checks
- Android app ID `app.pinduoduo.overlayru` unchanged; `versionCode 15`, `versionName 0.2.0-beta.5`.
- No extra photo/storage permissions, no screenshot capture, no image uploads. Recognition continues locally and translation still uses existing user-consented ML Kit models.
- Existing local glossary, paid license state and free overlay translation are preserved.
- Prior 47 JUnit tests plus five new bounded-decoder policy tests (52 expected).
- This is a **targeted bug fix**, not a claim of reproduction on the user's Android device. Exact failure cause from screenshot alone remains unconfirmed; on-device verification still required for cloud-backed URI providers.
- An in-place update from the beta4 Kotlin APK requires the **same certificate** (SHA-256 `d0d4e5dfb604917e1896c9a4697f2743296e3fa7b137d5bacefdf7a8c7b519d3`) and a higher versionCode. The older v0.1.x release certificate is incompatible.

## Real-device acceptance
1. Select an ordinary screenshot from the local Gallery and confirm the preview and text extraction.
2. Repeat with a cloud-backed picker item and any PNG, JPG, WebP and HEIC item supported by the device.
3. Test 20–60 Chinese labels with a downloaded translation model and verify the translated count advances.
4. Switch quickly between photos, rotate the phone and cancel the system picker; ensure no stale OCR result appears.
5. Check settings and local glossary still open and work. Checkout action labels remain protected from translation.
